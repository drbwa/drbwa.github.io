Astro rebuild: implementation and owner checklist

This is the working sequence for rebuilding drbwa.github.io on the existing astro-rebuild branch. It assigns each handoff, gives review criteria, and lists every action that needs Bruno's accounts or judgment. Open this file directly in a browser; it needs no server, fonts, or network connection. Checkboxes can be printed and are saved when the browser permits local storage for local files.

Build sequence

The implementer owns steps 0–6. Bruno's actions are collected below in the order they become necessary. The existing build spec, design and copy, launch runbook, and syndication addendum provide the detailed recipes. This plan resolves their handoffs and a few conflicts.

00

Freeze the baseline

Implementer Confirm a clean worktree and the branch; tag and push the last Jekyll commit as pre-astro. Capture the live URLs, response codes, titles and redirects in ignored .baseline/. Record existing /, /publications/, /blog/, /404.html, and the feed behavior.

Exit: remote tag exists and baseline can be compared with the new build. Keep Jekyll files through launch.

01

Scaffold and configure Astro

Implementer Follow DOC 02 P1: pinned dependencies and lockfile, scripts, ignore rules, Astro config, content schema, constants, CI and a deploy workflow limited to master. Add DOC 05's syndication schema and constants now. Select the unified Markdown processor explicitly; prove maths and heading anchors in an actual rendered page.

Exit: clean install, build and type check pass; malformed front matter fails with a useful file name; the branch CI run is green. Do not switch Pages source yet.

02

Build the design system and site shell

Implementer Add the three stylesheets, metadata, layouts, header, footer, theme toggle and static assets from DOC 02 P2 and DOC 03. Put the chosen domain in Astro site, SITE_URL, public/CNAME, and robots.txt. Keep the newsletter link as a plain link; add no Substack embed.

Exit: light, dark, OS preference and stored preference work; canonical, feed and sitemap links point to the same host; output includes CNAME and .nojekyll.

03

Implement and review the pages

Implementer + Bruno review Build home, writing index, publications, CV and 404. Use DOC 03 §5 copy, with DOC 05 §6's replacement writing intro. Get Bruno's factual and tone review before treating that copy as final. Check all old public URLs and keep the CV free of phone and street address.

Exit: Bruno approves the exact displayed copy; pages are navigable at narrow and wide widths; no placeholder or stale profile facts remain.

04

Finish the post pipeline

Implementer Implement the MDX route, /feed.xml, figures, callouts, Mermaid, maths, code highlighting and draft filtering. Add DOC 05's subscribe and syndication components. Make the draft fixture cover diagrams, charts, tables, maths and a syndicated link; verify it is absent from the production output.

Exit: content validation and rendering checks pass in both themes; the home page has no Mermaid bundle; subscription appears only on the writing index and posts; no iframe is introduced.

05

Test and prepare the release

Implementer + Bruno review Run DOC 04 §§1–3 plus DOC 05 §7: clean build, type check, link check, URL parity, feed/sitemap, accessibility, mobile widths, zero unwanted JavaScript, and live preview of the built output. Record results and exceptions in the pull request. Share a preview or local screenshots for Bruno's visual and copy review. Prepare a release note with exact DNS and Pages steps.

Exit: all required checks pass, Bruno approves the preview and the merge/cutover plan, and the rollback tag is available.

06

Launch, verify, and clean up

Bruno + implementer Bruno registers/configures the domain and changes GitHub Pages source to Actions at the agreed launch time. Merge astro-rebuild into master; watch the deployment and confirm the custom domain, certificate and HTTPS. Verify public URLs and old-host redirects. Then remove Jekyll files in a separate commit, update the root README, and submit the sitemap. Configure Substack before the first syndicated post.

Exit: canonical site and redirects work over HTTPS, domain ownership is verified, and the post-launch checks below are complete.

Corrections and checks before following the older recipes

  • These repo documents are snapshots: the rebuild index says its linked private artifacts may be newer. Before coding from a recipe, reconcile any newer artifact that Bruno supplies; record changes in this repository so the implementation has one reviewable source.
  • DOC 02 T4.2 has a stale exit condition: it says feed links should point to drbwa.github.io. They must point to the chosen canonical domain, as DOC 02 T1.8 and DOC 04 require.
  • DOC 02 P3 points at the wrong copy section: use DOC 03 §5, not §3. Use DOC 05 §6 for the revised writing-index intro and subscribe wording.
  • DOC 05 modifies P4 and the launch checks: implement its five build deltas and four checks as part of the main work, even though DOC 02–04 were written earlier.
  • Verify tool and service details at implementation time: compare pinned package APIs, GitHub Actions versions, DNS addresses and account screens with current official documentation. Keep the explicit unified Markdown processor; Astro's Markdown docs confirm why it is needed. Astro's Pages guide confirms public/CNAME for a custom domain.
  • DOC 04's domain procedure is a launch recipe, not proof the domains are registered: check ownership and current DNS before making changes. If drbwa.com is unavailable, omit that optional redirect and note it in the release.
  • DOC 03 copy is dated September 2026: Bruno must confirm all claims before publication. The old Jekyll pages do not establish that newer biographical claims are current.

Definition of complete

The work is complete when the approved Astro site is served at the confirmed canonical domain over HTTPS; the old public URLs redirect correctly; all required local, CI and manual checks pass; the custom domain is verified with GitHub; Jekyll has been removed in its own commit; the README explains the new publishing workflow; and Bruno can publish a post on the site and then syndicate it to Substack using section F.
