Astro Rebuild Build Spec

Every command and every file needed to turn drbwa.github.io from a Jekyll site into an Astro 7 site, in the order they should be run. Written to be executed literally.

Target astro 7.3.2 Node ≥ 22.12.0 Branch astro-rebuild Est. ~9 h to end of P4
§ 0

How to use this document

Work through the tasks in order. Every task has an ID, an action, and a Done when condition — do not move to the next task until that condition is literally true. Where a file's contents are printed, use them verbatim; where a file is described rather than printed, its content comes from DOC 03.

  • Do not upgrade the pinned versions. They are exact, not ranges, and they are known to work together as of September 2026. If npm install reports a peer conflict, stop and report it rather than adding --force.
  • Do not add libraries that are not listed here. No CSS framework, no UI kit, no animation library, no icon package.
  • Do not delete any Jekyll file until P6. The old site keeps serving until cutover.
  • Do not invent design. Colours, type and spacing come from DOC 03 §4 exactly.
Read this before writing astro.config.mjs

Astro 7 replaced its Markdown engine with Sätteri (Rust). Sätteri does not run remark or rehype plugins — it has its own mdastPlugins / hastPlugins API. If you set markdown.remarkPlugins or markdown.rehypePlugins without also installing @astrojs/markdown-remark and selecting it via markdown.processor, the build succeeds and your plugins do nothing at all. There is no warning. Maths will render as literal dollar signs and heading anchors will not exist. The config in T1.3 selects the unified processor explicitly. Do not "simplify" it away.

T1.8

The custom domain — the four places it appears

The site moves from drbwa.github.io to a custom domain registered at Cloudflare. The spec assumes brunowassermann.com. If Bruno chose a different one, change it in exactly these four files and nowhere else — a mismatch between them produces canonical URLs pointing at one domain and a feed pointing at another, which is worse than either alone.

FileWhat it setsConsequence if wrong
astro.config.mjssiteEvery canonical URL, every absolute link in the feed and the sitemap.
src/consts.tsSITE_URLAnything the templates build a URL from by hand.
public/robots.txtSitemap:Search engines fetch a sitemap on the wrong host and ignore it.
public/CNAMEthe domain, aloneGitHub Pages does not know the site has a custom domain at all.
public/CNAME, not a repo-root CNAME

With the legacy Jekyll builder, GitHub writes a CNAME file to the repository root when you set a custom domain in the settings UI. With an Actions deploy, GitHub only sees what the workflow uploads — so the file has to be in the build output. Astro copies public/ to the root of dist/, so public/CNAME becomes dist/CNAME, which is correct. A CNAME at the repository root does nothing and will be silently ignored.

The file contains the bare hostname on one line: brunowassermann.com. No https://, no trailing slash, no www unless www is the canonical host.

Done whengrep -rn "drbwa.github.io" astro.config.mjs src/ public/ returns nothing, and all four files agree on one hostname.

Create the three stylesheets

T2.2

BaseHead.astro

One component owns every <head> tag, so metadata cannot drift between pages.

Done when viewing source on any built page shows exactly one <title>, one canonical link, and the RSS alternate link.

T2.3

Base.astro, Header, Footer, ThemeToggle

Header.astro — the site name as a link to /, the four NAV entries from consts.ts, and ThemeToggle. Mark the current page with aria-current="page" by comparing Astro.url.pathname to each href. No hamburger menu: at narrow widths the four links wrap onto a second line, which is fine and is one fewer thing to break.

Footer.astro — the ELSEWHERE links, the copy from DOC 03 §3.6, and the current year via new Date().getFullYear().

Why data-theme specifically

astro-mermaid reads data-theme on the root element to pick its diagram palette. Using any other attribute name means diagrams stay light-themed on a dark page.

Done when the toggle flips the page, the choice survives a reload, and a fresh private window follows the OS setting.

T2.4

Page.astro and static assets

Page.astro wraps Base and renders a page title plus a <slot /> inside <div class="prose">, importing ../styles/prose.css. Used by publications, cv and 404.

Also create an empty public/.nojekyll (stops GitHub Pages ever trying to run Jekyll over the output) and public/favicon.svg per DOC 03 §7.

Done whendist/robots.txt, dist/CNAME, dist/.nojekyll, dist/favicon.svg and dist/sitemap-index.xml all exist after a build.

T3.6

Recent posts on the home page

Drafts

The !data.draft filter must be applied in four places: the home page, the blog index, the feed, and getStaticPaths. Miss the last one and drafts are unlisted but still publicly reachable at their URL.

Done when a post with draft: true appears nowhere in dist/: grep -rl "the draft title" dist/ returns nothing.

P4

The blog pipeline

T4.1

The post route

Astro 5 and later use the content layer: entries are addressed by id, not slug, and rendering goes through render(entry) imported from astro:content rather than entry.render(). Older tutorials get this wrong.

Post.astro wraps Base with type="article", renders the title, the date via <time datetime={...}>, an optional "Updated" line, the tags as plain text, then the slot inside <article class="prose">. It also imports prose.css and katex/dist/katex.min.css.

KaTeX CSS

Maths renders as unstyled markup unless katex/dist/katex.min.css is imported. Import it in Post.astro only, so it does not weigh down pages with no maths on them.

Done when a post at src/content/blog/x.mdx is reachable at /blog/x/ in npm run dev.

T4.2

The feed — at /feed.xml, not /rss.xml

The Jekyll site published its feed at /feed.xml via jekyll-feed. Astro's examples default to /rss.xml. Keeping the old path is a hard requirement; anything else silently unsubscribes existing readers.

Done whendist/feed.xml exists, is valid XML, and every <link> is an absolute https://drbwa.github.io/blog/…/ URL.

T4.3

Figure.astro — figures and charts

One component covers photographs, screenshots and charts, including charts exported from matplotlib as SVG. The srcDark prop exists because a chart exported on a white background is unreadable on a dark page; when only one source is given it is used for both themes.

The alt text rule

alt is required by the type, and Astro's <Image> will error without it. That is deliberate: an uncaptioned, undescribed chart is unusable to a screen reader. The dark variant takes alt="" and aria-hidden so the same figure is not announced twice.

.only-light and .only-dark are defined in prose.css (DOC 03 §4.3) and switch on the same three theme states as everything else.

Done when a figure with both sources shows exactly one image in each theme, and the caption sits under the image.

T4.4

Callout.astro

A small MDX component for asides: <Callout type="note|warn">…</Callout>. Renders an <aside> with a mono label and a left rule, styled from the tokens. No icons, no emoji.

Done when both variants render in the fixture post in both themes.

T4.5

The kitchen-sink fixture post

This post exists to prove the pipeline works and is never published. Create it with draft: true and keep it in the repo permanently — it is the regression test for every future dependency upgrade.

Also create src/content/blog/_assets/example-chart.svg — any small valid SVG will do for now.

Done when in npm run dev at /blog/_pipeline-check/: the diagram renders as a diagram, the maths renders as maths, the figure and caption appear, the code block is syntax-highlighted, the table scrolls rather than overflowing, and all of it is legible in both themes. Then confirm the page is absent from dist/ after npm run build.

T4.6

Verify Mermaid does not leak onto other pages

Done whendist/index.html references no bundled JavaScript at all — only the small inline theme script from BaseHead. If a large Mermaid bundle is linked from the home page, stop and report it rather than working around it.
